# CTI · AI 기반 경쟁기술 인텔리전스

**C**ompetitive **T**echnology **I**ntelligence — 경쟁사의 **특허 · 설비투자 · 컨퍼런스 발표**를 상시 수집·분석해,
배터리 제조 공정 기술트리 위에서 **자사에 없는 기술**을 근거와 함께 드러내는 단일 파일 대시보드.

## 파일 구성

```
index.html    화면 전체 (HTML + CSS + JS 단일 파일, 외부 의존성 없음)
```

브라우저에서 `index.html`을 그대로 열면 동작합니다. 현재는 `USE_API=false` 상태라
내장 목업(`TREE_MOCK`)으로 렌더링되며, 화면 우상단에 **MOCK** 배지가 표시됩니다.

## 화면 구성

| 영역 | 내용 |
|------|------|
| 소스 스트립 | 수집 상태(LIVE/MOCK) · 소스별 누적/증분 건수 · 수집 시각 |
| KPI 4종 | 미보유 기술 · 양산 확인된 격차 · 일부/검토 단계 · 추적 경쟁사 |
| 공정 레인 GAP 맵 | 1 셀 = 1 세부기술. 보유(먹) / 일부(앰버) / 미보유(마젠타) |
| 기술 트리 | 공정 → 세부공정 → 세부기술 3단 트리, 검색 지원 |
| 기술 상세 | 기술 설명 · 왜 중요한가 · 보유 매트릭스 · 근거 사다리 · 자사 4채널 · 출처 계보 · 근거 원문 · 판정 한계 |
| GAP 백로그 | 시급도 점수 정렬 표, 경쟁사 필터, CSV 내려받기 |

## 판정 규칙

**근거 등급 4단계**

| 등급 | 정의 |
|------|------|
| `VERIFIED` | 양산 라인 가동이 1차 출처로 확인됨 |
| `STRONG` | 파일럿 라인 신설·착공 또는 양산 일정 공식 언급 |
| `MEDIUM` | 등록특허의 구체적 공정 조건 또는 기술세션 발표 |
| `WEAK` | 공개특허(출원) 또는 포스터·패널 언급 |

- **보유 판정** — STRONG 1건 · MEDIUM 2건 · WEAK 3건 이상
- **TRL 8 이상** — 서로 다른 소스 2종이 교차 확인될 때만 부여
- **미보유(GAP)** — 자사 4채널(특허·라인·발표·내부과제)이 모두 비었고 경쟁사 보유 신호가 있을 때
- 신호 0건은 "경쟁사 미보유"가 아니라 **"관측되지 않음"** 으로 표기합니다.

각 노드는 `lim` 필드에 **이 판정의 한계**를 함께 싣습니다. 근거의 강도와 사각지대를 화면에 드러내는 것이 이 도구의 전제입니다.

## 백엔드 연결

파이프라인이 준비되면 `index.html` 상단의 스위치 **두 줄만** 바꾸면 됩니다.

```js
const API_BASE = "";        // 같은 오리진이면 빈 문자열
const USE_API  = false;     // true 로 변경
```

`USE_API=true`이면 `API_BASE + "/api/tree"` 를 호출하고, 실패 시 목업으로 자동 폴백하며
화면에 실패 사유를 표시합니다. `adaptApi()`가 백엔드의 flat node 응답을 화면 내부 구조로 변환합니다.

## 남은 작업

- `/api/tree` 백엔드 파이프라인 구현 후 `USE_API=true` 전환
- 자사 4채널(특허·라인·발표·내부과제) 값의 사내 시스템 연동 — 현재는 공정기술팀 확인값 수기 입력
- 스냅샷 도구(`APP_VERSION` 자동 치환) 및 `versions/` 보관본 체계
- 판정 기준선 합의 — 예: 크랙 검사의 '검출만' vs '폐루프 보정 연동'을 어디서 가를 것인가
