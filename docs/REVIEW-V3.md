## 2. 빈틈과 맹점

### 2-1. 경쟁사 하나가 법인명 10개로 흩어져 있다 — 가장 큰 맹점

BigQuery 실측 결과:

| 실제 기업 | 등록된 법인명 수 | 합계 |
|---|---:|---:|
| PANASONIC | 10개 이상 | 300,000+ |
| CATL | 5개 (`CONTEMPORARY AMPEREX`, `NINGDE CONTEMPORARY`, `…HONG KONG`, `JIANGSU…`) | 49,225 |
| BYD | 5개 (`BYD CO`, `BYD PREC MFG`, `SHENZHEN BYD AUTO`, `HUIZHOU BYD`…) | 55,000+ |
| TESLA | 3개 (`TESLA INC`, `TESLA NP`, `TESLA MOTORS`) | 5,351 |

`CATL` 로만 검색하면 **`NINGDE CONTEMPORARY AMPEREX` 20,819건을 통째로 놓친다.**
현재 코드에는 법인명 통합(name normalization) 장치가 없다.

### 2-2. 경쟁사 설비투자는 원천이 비어 있다

| 원천 | 대상 | 기간 | 전체 공시 | 설비투자 |
|---|---|---|---:|---:|
| DART | 삼성SDI | 2023-01~2026-09 | 366 | **0** |
| DART | SK온 | 2023-01~2026-09 | 169 | **0** |
| cninfo | CATL | 2022-01~2026-09 | 544 | 6 (전부 2022~2023) |
| cninfo | BYD | 2022-01~2026-09 | 416 | **0** |

- **SK온**: 비상장이라 거래소 자율공시 의무가 없다.
- **삼성SDI**: 공시 제목을 전수 확인했으나 시설투자 계열이 한 건도 없다.
- **CATL**: 2024년 이후 `投资建设` 공고가 끊겼다. 2025년 홍콩 상장 이후 HKEX 로 옮겨간 것으로 **추정**.
- **BYD**: cninfo 상 orgId 가 `gshk0001211`(홍콩)이다. 공고가 HKEX 로 빠진다.

> **결론** — 설비투자 신호를 원하면 **HKEX 공시를 새로 붙여야 한다.** 이것이 현재 가장 큰 단일 공백이다.

### 2-3. 화면과 수집이 아직 연결돼 있지 않다

화면(`index.html`)은 여전히 `TREE_MOCK` 목업 61건을 그린다. 어댑터가 만든
실제 evidence(127건)는 `data/*.jsonl` 에 있을 뿐 화면으로 가지 않는다.
**둘을 잇는 노드 매핑 단계가 통째로 비어 있다.**

## 3. 비용 — 지금 돈이 드는 곳은 BigQuery 하나뿐이다

### 무료

| 원천 | 과금 | 제약 |
|---|---|---|
| KIPRIS Plus | **0원** | 일일 호출 한도(계정별) |
| cninfo | **0원** | 공식 API 아님 — 예의 있는 호출 간격 필요 |
| DART | **0원** | 일 20,000회 |
| SEC EDGAR | **0원** | User-Agent 에 연락처 필수 |

### 과금 — BigQuery

BigQuery 는 **읽은 컬럼의 바이트**만큼 과금한다. 이 테이블은 파티셔닝이 없어
**WHERE 절로는 비용이 전혀 줄지 않는다.**

| SELECT 컬럼 | 누적 | 증가 |
|---|---:|---:|
| `publication_number` | 2.49 GB | +2.49 |
| `+ title_localized` | 18.27 GB | +15.78 |
| `+ assignee_harmonized` | 22.37 GB | +4.10 |
| `+ cpc` | 36.46 GB | **+14.09** |
| `+ 날짜·family·country` | 43.01 GB | +6.55 |
| `abstract_localized` 포함 | 196.48 GB | **+153.47** |

- 현재 검색 1회 = **40.30 GB**
- 무료 한도 월 1 TiB → **월 약 25회**
- 초과 시 **1 TiB 당 $6.25** (40GB ≈ **$0.24/회**)
- `COUNT(*)` 는 메타데이터라 **0원**

**지금까지 실제 사용량: 약 88 GB (무료 한도의 8.6%).** 추가 과금 발생하지 않았다.

### 위험

`abstract_localized` 를 켠 검색(234 GB)을 5회만 돌리면 무료 한도를 넘는다.
`MAX_SCAN_GB=45` 가드가 이를 막고 있으나, **상한을 올리면 바로 과금된다.**

## 4. 더 땡겨오려면 — 분량과 일정

### 핵심 전환: "검색"에서 "적재"로

현재는 물어볼 때마다 1억 7천만 행을 훑는다(40GB). 이건 검색 도구의 방식이지
인텔리전스 제품의 방식이 아니다. **한 번 퍼와서 로컬에 쌓고, 그다음부터는 공짜로 조회**해야 한다.

### 1회 적재 비용 (추정)

| 범위 | 방식 | 예상 스캔 | 예상 비용 | 결과 |
|---|---|---:|---:|---:|
| 경쟁사 6사 전체 특허 | assignee 필터 + 청구항 | 약 250 GB | **약 $1.5** | 약 50만 건 |
| 배터리 CPC(H01M) 전체 | CPC 필터 + 청구항 | 약 400 GB | **약 $2.5** | 약 150만 건 |
| 증분 갱신 (분기 1회) | 신규 공개분만 | 약 40 GB | 무료 한도 내 | — |

> 한 번에 $1.5~2.5 면 **경쟁사 전체 특허를 통째로 확보**한다. 지금처럼 검색 25회에
> 무료 한도를 소진하는 것보다 압도적으로 싸다.

## 5. 중복·허위를 거르는 구조

### 있는 것

| 장치 | 동작 | 검증 |
|---|---|---|
| 등급 사다리 | VERIFIED/STRONG/MEDIUM/WEAK 4단계 | ✅ |
| 등급 근거 보존 | `grade_basis` 에 판단 근거 원문 구절 | ✅ |
| 자동 확정 금지 | VERIFIED 는 규칙이 맞아도 사람 확인 대상 | ✅ 테스트 고정 |
| 노드 매핑 불가 표시 | 기술 키워드 0개면 `needs_review` | ✅ 테스트 고정 |
| 노이즈 필터 | M&A·회사채·내부규정 제외 | ✅ 테스트 고정 |
| 출처 원문 링크 | 모든 레코드에 원문 URL | ✅ |
| ID 기반 중복 제거 | 어댑터 내부에서 출원번호·공고ID 기준 | ✅ |

### 없는 것 — 이게 문제다

| 빠진 장치 | 왜 문제인가 |
|---|---|
| **특허가족 병합** | 같은 발명의 KR·US·CN·EP 출원이 **4건으로 세어진다.** 경쟁사 특허 수가 부풀려진다 |
| **법인명 통합** | §2-1. 한 회사가 여러 회사로 세어지거나 통째로 누락된다 |
| **어댑터 간 중복 제거** | KIPRIS 와 BigQuery 가 같은 KR 특허를 각각 넣으면 막을 장치가 없다 |
| **날짜 교차 검증** | 공시일과 실제 착공일이 다를 때 검출 못 함 |
| **사람 확인 워크플로** | `needs_review` 플래그만 있고 **확인하는 화면이 없다** |

> 현재 구조는 **"틀린 것을 표시는 하지만 걸러내지는 못한다."**
> 표시된 것을 사람이 볼 화면이 없기 때문이다.

## 7. 표본 크기 — 작지 않다

"몇 백 건"으로 보인 이유는 **화면이 목업 61건을 그리고 있기 때문**이다. 원천에는 이만큼 있다.

| 원천 | 실측 보유량 |
|---|---:|
| BigQuery 전체 | **170,418,479건** |
| PANASONIC 특허 | 300,000+ |
| SAMSUNG SDI 특허 | 79,862 |
| BYD 특허 | 55,000+ |
| LG에너지솔루션 특허 | 51,960 |
| CATL 특허 | 49,225 |
| KIPRIS `분리막` | 734,274 |
| KIPRIS `전극 코팅` | 233,556 |
| KIPRIS `이차전지` | 88,306 |

> 앞서 "8건"이 나온 것은 제가 `limit=8` 로 **8건만 요청**했기 때문이다.
> 데이터 부족이 아니라 요청 크기 문제였다.

**임원 보고에서 "수백 건"으로 보이면 안 된다.** §4의 적재 단계를 거치면
화면에 수만~수십만 건 기반의 판정이 올라간다.
