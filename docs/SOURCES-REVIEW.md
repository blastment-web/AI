# 수집 창구 심층 검토 — 더 가져올 곳이 있는가

2026-09-13 · 모든 판정은 그날 실제로 호출해 본 결과다. 추측으로 적은 줄은 없다.

---

## 1. 한 줄 결론

**키 없이 더 가져올 곳은 사실상 다 붙였다.** 남은 것은 전부 회원가입·키 발급이 필요하고,
그중 실제로 빈칸을 메우는 건 **EDINET(파나소닉)** 과 **EPO OPS(청구항 원문)** 둘뿐이다.
나머지 후보는 이미 붙인 창구와 내용이 겹쳐서, 붙여도 숫자만 늘고 판단은 달라지지 않는다.

| **HKEX** | 없음 | **0건 (확정)** | 형식은 고쳤다. 고치고 보니 원천에 내용이 없었다 (§2.2) |

합계 **41,685건 → 42,071건**. 건수 증가폭보다 중요한 건, 그동안 "원천에 없다"고
적어 둔 항목 상당수가 **원천이 아니라 우리 쪽 문제**였다는 점이다.

### 2.1 SEC — 국가 차단이 아니었다

이전 보고서에 "한국 IP 차단(403)"이라고 적었다. **틀린 진단이었다.**
같은 IP에서 User-Agent만 바꿔 확인한 결과:

```
"LGES-CTI-research blastment@naver.com"   → 403
"Mozilla/5.0 ... Chrome/120.0.0.0 ..."    → 200
```

SEC 규약은 "연락처를 밝히라"고 요구하는데, 정작 방화벽은 브라우저가 아닌 UA를 막는다.
그래서 UA는 브라우저 문자열을 쓰고, 연락처는 그 용도의 표준 헤더인 `From:` 에 담았다.
신원을 밝히라는 규약의 요구는 그대로 지킨다. 호출 간격도 규약대로 지킨다.

여기서 예상 밖의 소득이 하나 나왔다. 제출목록만 보는 대신 **본문 전문검색**을 붙였더니,
우리가 추적하던 6사가 아니라 **미국 배터리 기업 50곳**이 걸렸다.

| 기업 | 건수 | 왜 중요한가 |
|---|---|---|
| QuantumScape · Solid Power · SES AI | 145 | 전고체 — 우리가 열위로 잡은 영역 |
| Amprius · Enovix | 69 | 실리콘 음극 |
| **Matthews International** | 14 | **건식 전극 장비 공급사** |
| Tesla | 7 | 4680 |

**Matthews International 이 특히 중요하다.** 건식 전극 롤프레스 장비를 만드는 회사다.
경쟁사가 이 회사에서 장비를 사면, 그 사실이 경쟁사 공시보다 먼저 여기 나타난다.
지금 화면은 이들을 "추가 관측 기업"으로만 싣고 6사 판정에는 넣지 않았다.

### 2.2 HKEX — 형식은 고쳤고, 고치고 보니 원천이 비어 있었다

BYD 설비투자의 유일한 원천으로 보고 붙였다. 계속 0건이었는데, 실패가 오류로 안 나고
조용히 빈 결과로 와서 원인을 찾기 어려웠다. 확정한 형식:

- 날짜 필드는 `from`/`to` (`fromDate`/`toDate` 아님), 형식은 `YYYYMMDD`
- `documentType`·`t1code`·`t2Gcode`·`t2code` 는 **빈 문자열**. `-1` 을 넣으면 0건
- `stockId` 는 종목코드가 아니라 내부 id (BYD `2696`, CATL `1000259940`)
- `titleSearchServlet.do` 는 '더 보기' 전용이라 단독 호출은 늘 0건

이 내용은 `adapters/capex_hkex.py` 머리말에 적어 뒀다. 같은 곳에서 또 막히지 않게.

**그런데 형식을 고치고 나니, 원천 자체에 설비투자 공시가 없었다.**
BYD 제목은 거의 전부 `海外監管公告`(포장지)라 제목만으로는 알 수 없어서,
포장지 **PDF 본문까지 전부 열어** 확인했다.

| 회사 | 공시 | 포장지 PDF 확인 | 설비투자 |
|---|---|---|---|
| BYD | 2,824건 | **924건 열어 봄** | **0건** |
| CATL | 566건 | **187건 열어 봄** | **0건** |

중간에 66건이 잡힌 적이 있는데 전부 월간 `產銷快報`(생산·판매 정기공시)였고,
3건이 잡힌 적도 있는데 `募集资金` 사용처 보고였다. 둘 다 새 투자 결정이 아니라서 뺐다.
**BYD·CATL 은 공장 투자를 홍콩에 개별 공시로 내지 않는다.** 회사 규모 대비 공시 의무
기준에 걸리지 않기 때문으로 보인다. 어댑터는 남겨 둔다 — 앞으로 나오면 자동으로 잡힌다.

### 2.3 DART — 조용한 절단

`list.json` 이 한 조회당 500건에서 잘린다. 오류가 아니라 그냥 최근 것만 온다.
2018~2026을 한 번에 부르니 최근 2년치 일상 공시만 오고 시설투자 공시는 뒤로 밀려 사라졌다.
**연 단위로 잘라** 부르도록 고쳤다 (삼성SDI 500 → 753건).

필터도 좁았다. `신규시설투자`·`유형자산취득` 만 보면 3건뿐이다.
`타법인주식취득`·`단일판매공급계약`·`기타경영사항` 을 2차 등급으로 함께 담아 201건이 됐다.
다만 이 2차분은 설비투자라고 **단정하지 않는다.** 등급을 WEAK 으로 눌러 두고
`needs_review` 를 항상 켠다. 숫자를 늘리려고 사실을 끌어올리지는 않았다.

### 2.4 cninfo — 원천의 한계

기간을 2022→2018로 넓혀 16→23건. 여기가 사실상 천장이다.
키워드 없이 전체를 훑어도 봤는데, cninfo 의 전체 목록 페이징은 조용히 잘려서
정작 설비투자 공고가 빠진다(전체 1,470건을 받아도 그 안에 없다). 제목 검색만이 유효하다.

그리고 23건이 적은 게 아니다. 이건 **이사회 의결 수준의 대형 공장 투자**라서
원래 연 5건 안팎이다. CATL 이 실제로 그만큼만 발표한다.

### 2.5 OpenAlex — 특허 말고 두 번째 눈

지금까지 경쟁사 근거가 사실상 특허뿐이라, 판정에 늘 "특허 기준" 단서가 붙었다.
TRL 8 이상은 서로 다른 소스 2종이 교차해야 주도록 해 놨는데, 2종이 될 수가 없었다.
논문·학회 발표가 붙으면 이 문제가 풀린다.

CIBF·AABC 같은 산업 컨퍼런스는 공개 API가 없다. OpenAlex 는 학회 프로시딩과
저널을 함께 색인하고 키가 필요 없어서 이걸 대신한다.

주의할 점 두 가지를 실측으로 확인했다.
- 기관 검색으로 회사를 찾으면 안 된다. LG에너지솔루션·삼성SDI 는 기관 레코드가 없고,
  `Tesla` 로 찾으면 체코의 동명 회사가 나온다. 저자 소속 **문자열**을 봐야 한다.
- 소속만으로 거르면 `SK On` 이 본문의 "SK on ..." 에 걸려 3,414건이 된다.
  반드시 기술어 검색과 교차해서 써야 한다.

## 3. 검토했으나 붙이지 않은 곳

전부 2026-09-13 실제 호출 결과다.

| 후보 | 응답 | 판단 |
|---|---|---|
| **EDINET** (일본 금융청) | 401 — 키 필요 | **붙여야 한다.** 파나소닉 설비투자의 유일한 원천 |
| **EPO OPS** | 403 — 키 필요 | **붙여야 한다.** 청구항 원문 → 분류 정확도 |
| USPTO PatentsView | 구 API 폐지, 신 API 키 필요 | 불필요. 미국 특허는 BigQuery 에 이미 있다 |
| Lens.org | 401 — 키 필요 | 불필요. BigQuery 와 겹친다 |
| WIPO PATENTSCOPE | 403 — 공개 API 없음 | 불가 |

### 왜 문헌 API를 더 붙이지 않았나

Crossref 는 키 없이 바로 됐다. 그런데 OpenAlex 가 이미 같은 논문을 색인한다.
붙이면 근거 건수는 늘지만 **같은 논문이 두 번 세어질 뿐** 판단은 달라지지 않는다.
숫자를 키우는 것과 판단을 좋게 하는 것은 다른 일이다. 그래서 뺐다.

## 4. 영향도 분석 — 붙이면 시스템이 견디는가

### 4.1 구조

새 창구를 붙여도 구조는 바뀌지 않는다. 어댑터는 전부 같은 계약을 지킨다.

```
adapters/*.py  →  data/evidence_*.jsonl  →  pipeline/build_tree.py  →  data/tree.json  →  화면
                   (type·company·date·grade·url)
```

`build_tree.py` 는 `data/evidence_*.jsonl` 을 글롭으로 읽는다.
**파일만 떨구면 자동으로 합류한다.** 이번에 SEC·HKEX·OpenAlex 를 붙일 때
`build_tree.py` 는 한 줄도 고치지 않았다.

### 4.2 비용

| 창구 | 키 | 비용 | 한도 |
|---|---|---|---|
| BigQuery | 있음 | **스캔량 과금** — 검색 1회 ≈ 40GB | 월 1TiB 무료. 현재 166GB 사용 |
| KIPRIS · DART | 있음 | 무료 | 일일 호출 한도 |
| SEC · HKEX · cninfo · OpenAlex | 불필요 | 무료 | 예의 호출 간격만 |
| EDINET · EPO | **필요(미발급)** | 무료 | 발급 후 확인 |

**BigQuery 만 돈이 든다.** 이 표에서 유일하게 주의할 줄이다.
`MAX_SCAN_GB=45` 로 상한을 걸어 두었고, 쿼리 전 dry-run 으로 비용을 미리 잰다.

### 4.3 위험

| 위험 | 실제로 일어난 일 | 대응 |
|---|---|---|
| 조용한 실패 | HKEX·DART 가 오류 없이 빈 결과를 줬다 | 수집량을 화면에 노출. 0건이면 눈에 띈다 |
| 회사명 오탐 | `SK On` 이 3,414건으로 부풀었다 | 기술어와 교차 필수 |
| 중복 계상 | 같은 발명이 나라별로 여러 건 | **미해결** — 특허가족 병합 필요 |
| 호출 차단 | OpenAlex 429 | 재시도·간격 조절 적용 |
| 키 유출 | — | `.env` 격리 + 로그 `redact()` + `.gitignore` |

**제일 큰 남은 위험은 중복 계상이다.** 창구를 늘릴수록 같은 발명을 여러 번 셀 확률이 올라간다.
특허가족 병합 전까지는 건수를 '규모의 눈금'으로만 읽어야 하고, 절대값으로 믿으면 안 된다.

### 4.4 성능

전체 재수집이 약 40분(HKEX PDF 본문 확인 포함). 증분 수집은 `data/state.json` 이
받아 둔 지점을 기억해서 새 것만 받는다. 화면은 데이터를 파일에 박아 넣어 서버 없이도 열린다.

## 5. 다음에 할 일 — 순서대로

| 순위 | 할 일 | 얻는 것 | 필요한 것 | 기간 |
|---|---|---|---|---|
| 1 | **자사 보유 현황 확정** | 판정의 신뢰 자체 | 공정기술팀 확인 | 3일 |
| 2 | **특허가족·회사명 병합** | 중복 제거 → 건수를 믿을 수 있게 | 없음 | 2일 |

| 4 | **EPO OPS 연결** | 청구항 원문 → 분류 정확도 | **키 발급 대기 중** | 1일 |
| 5 | SEC 신규 관측 50사 편입 | 전고체·실리콘음극 조기경보 | 없음 | 2일 |

### 키를 받아 주셔야 하는 것

- **EDINET** — https://api.edinet-fsa.go.jp 회원가입 → Subscription Key 발급 (무료)
  `.env` 에 `EDINET_API_KEY=...` 로 넣어 주시면 바로 붙입니다.
- **EPO OPS** — 이미 가입하셨다고 하셨습니다. Consumer Key/Secret 을
  `.env` 에 `EPO_KEY=` / `EPO_SECRET=` 으로 넣어 주십시오.

키 값은 채팅에 붙여넣지 마시고 `.env` 파일에 직접 적어 주십시오.

## 6. 정직하게 남겨 두는 것

- **BYD 설비투자는 0건이다.** cninfo 전 키워드, HKEX 공시 2,824건, 그중 포장지 PDF
  924건 본문까지 확인한 결과다. **숫자를 못 찾은 게 아니라 원천에 없다.**
  BYD 를 설비투자로 추적하는 건 포기하고, 특허와 논문으로만 본다.
- **파나소닉 설비투자도 0건이다.** 2013년 NYSE 상장폐지라 SEC 에 제출이 없다(404 확인).
  EDINET 이 유일한 길이고 키가 필요하다.
- 기존에 '미보유'로 적혀 있던 18개 기술 전부에서 자사 특허가 검색된다.
  이건 데이터 문제가 아니라 **확인이 안 된 상태**다. 1순위로 둔 이유다.
