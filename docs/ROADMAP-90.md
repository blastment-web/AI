> 2026-09-12 기준. 현재 완성도 **약 55%**. 모든 수치는 실호출 측정값이다.

## 병목은 하나다 — "이 특허가 어느 기술의 것인가"

경쟁사 특허 **40,000건**을 확보했다. 그런데 57개 기술 중 어디에 속하는지
**확실히 판정할 수 있는 것은 228건뿐**이다.

용어가 겹치는지로 판단하기 때문이다. 임계값을 낮추면 이렇게 된다.

| 임계값 | 판정에 쓴 근거 | 한 기술에 붙은 최대 건수 | 신뢰도 |
|---:|---:|---:|---|
| 2.0 | 31,046건 (74%) | **7,674건** | 못 쓴다 — "코팅" 한 단어만 겹쳐도 배정 |
| 6.0 | 2,066건 (5%) | 600건 | 여전히 과함 |
| **8.0** | **228건 (0.5%)** | **51건** | **쓸 수 있다 — 현재 설정** |

그래서 화면은 **확실한 것만 판정에 쓰고**, 애매한 것(30,818건)은
`관련 가능성`으로 분리해 숫자에서 뺐다. 부풀리지 않기 위해서다.

**해결책은 AI 판독이다.** 제목·초록을 읽고 "이것은 건식 전극 코팅 기술이다"를
판별하면 4만 건 대부분을 제대로 분류할 수 있다. 약 5일.

## 2번이 가장 중요하다 — 자사 보유 현황

기존 기록에서 "미보유 · 4개 채널 모두 0" 이라던 **16개 기술 전부**에서
자사 명의 특허가 검색되었다.

| 기술 | 기존 기록 | 검색된 자사 특허 |
|---|---|---:|
| 무용매 건식 코팅·라미네이션 | "4개 채널 모두 0" | 27건 (+ 관련 2,859건) |
| 저온 건조 (IR·유도가열) | "출원 2건, 라인 적용 0" | 다수 |
| 레이저 실링 (파우치) | "4개 채널 모두 0" | 다수 |
| 케이스 레이저 용접 감시 (OCT) | "특허·파일럿·발표 모두 0" | 다수 |

**둘 중 하나다.**
1. 기존 기록이 오래되었다 — 그 사이에 출원했다
2. 검색이 다른 기술의 특허를 잘못 집었다

**어느 쪽이든 임원 보고 전에 반드시 확인해야 한다.** "우리는 이 기술이 없습니다"라고
보고했는데 자사 특허가 27건 있으면 보고 전체의 신뢰가 무너진다.

화면에서 해당 기술을 누르면 **주황색 경고**가 뜨고, `LGES` 칸을 누르면 어떤 특허인지
목록과 원문 링크가 나온다. 생산기술혁신센터이 그 목록을 보고 판단하면 된다.

## 남은 창구 4개를 어떻게 연결하나

### 1. SEC EDGAR (테슬라 설비투자) — 가장 쉽다

- **키 불필요.** 요청 헤더에 연락처 이메일만 넣으면 된다
- 엔드포인트: `https://data.sec.gov/submissions/CIK0001318605.json` (테슬라 CIK)
- 8-K 공시에서 설비투자 항목을 고른다
- **작업량 1~2일.** DART 어댑터와 구조가 거의 같다

### 2. 컨퍼런스 프로그램 — 키는 없지만 손이 많이 간다

- CIBF·AABC·The Battery Show 등은 **공식 API 가 없다**
- 행사별로 프로그램 PDF 또는 세션 목록 웹페이지를 파싱해야 한다
- 행사마다 형식이 달라 **개별 구현**이 필요하다
- **작업량 4~5일** (행사 5개 기준). 매년 형식이 바뀌면 손봐야 한다

### 3. USPTO ODP (미국 특허 청구항)

- **키 필요.** `data.uspto.gov` 에서 발급 — USPTO.gov 계정 + MFA + 프로필 추가 항목
- 다만 **BigQuery 로 이미 미국 특허를 받고 있다.** 청구항 원문이 꼭 필요할 때만 쓰면 된다
- **후순위 권장.** 지금 필요한 것은 청구항이 아니라 기술 분류다

### 4. EPO OPS (유럽·PCT + 특허가족 ID)

- **키 필요.** `developer.epo.org` 에서 Consumer Key/Secret 발급 (무료, OAuth2)
- 값어치는 특허 자체보다 **INPADOC 특허가족 ID** 에 있다 — 위 3번 과제(중복 제거)의 핵심
- 다만 BigQuery 의 `family_id` 로도 상당 부분 대체된다
- **작업량 2일.** 키를 받아주시면 제가 연결한다

### 5. HKEX (홍콩 공시) — 새로 발견된 필요

- CATL 은 2024년 이후, BYD 는 처음부터 설비투자 공고가 **홍콩으로 빠진다**
- cninfo 로는 중국 경쟁사 설비투자를 더 이상 잡을 수 없다
- **작업량 3일.** 키 불필요

**권장 순서** — SEC(쉬움) → HKEX(공백이 큼) → 컨퍼런스(손이 감) → EPO → USPTO(후순위)

## 증분 수집은 이미 작동한다

"돌릴 때마다 똑같은 것을 다시 찾으면 의미가 없다"는 지적은 정확했고, 해결했다.

```bash
python -m pipeline.collect          # 새 것만 가져와 누적
python -m pipeline.collect --full   # 상태를 무시하고 전부 다시
```

`data/state.json` 에 소스별로 **이미 훑은 검색어와 마지막 수집 시점**을 기록한다.
실제 동작 확인:

| 실행 | 결과 |
|---|---|
| 1회차 | 817건 신규 추가 |
| 2회차 | 729건 신규 추가 (호출 제한에 걸렸던 검색어) |
| 3회차 | **0건 — "모든 노드를 이미 훑었습니다"** |

저장은 항상 병합이다. 같은 ID 가 다시 오면 `first_seen`(처음 본 날)을 유지한 채
내용만 갱신하므로, 언제 처음 나타난 신호인지 추적할 수 있다.

## 전체 실행 순서

```bash
python -m pipeline.collect            # 1. 증분 수집 (새 것만)
python -m adapters.patent_bq          # 2. 경쟁사 특허 대량 추출 (BigQuery, 39GB)
python -m pipeline.build_tree         # 3. 기술트리에 매핑 + 판정
python -m pipeline.render_html        # 4. dist/index.html 생성 (자체 완결형)
```

2번은 비용이 드니 분기 1회면 충분하다. 1·3·4번은 매일 돌려도 0원이다.
